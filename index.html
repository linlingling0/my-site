LiPowerline Agent · 培训案例（简要版 · 案例二）

用 Agent 搭建专用工具 变电站航线台账信息更新：从一句「对不上」，到一个双击就能用的工具

10走过的卡点
719/719引用更新成功
0 / 62异常（城南/都梁）
12 项独立验收全过
1 个 exe交付使用者

1为什么做它：手工 vs 工具

手工方式

  • 7 个航线 JSON、362 个部件点、722 处台账引用，全靠手改
  • 同一设备名称在文件里存了三份，改一处漏两处
  • 整体读写一遍就改坏格式（浮点、键序、空数组写法）
  • 改完无法证明没改错；出错是静默的

现在的方式

  • 填 4 个路径 → 预检（只出报告）→ 人工确认 → 正式执行
  • 只改白名单字段，其他字节一字不差
  • 异常一律保持旧值 + 进清单，绝不替人挑
  • 自动出全套报告 + 独立验收 12 项，与历史交付逐字节一致

2一步一步做出来：十步，每步都有一道坎

1明确边界

坎：需求只有一句话，连改成什么样都没说。
怎么说：先别动文件，把「要改 / 不许改 / 出错怎么办 / 怎么算完成」列成清单，我确认了再动手。

产出：需求清单 + 禁止清单
2摸清数据

坎：文件不敢碰，读写一遍格式就变。
怎么说：先做实验：原样读进来写出去，逐字节比差异，不许改生产文件。

产出：数据结构清单；结论：只能文本级定点替换
3确定规则

坎：名称怎么拆、分区取第几段、一对多怎么办，没人说清。
怎么说：能确定的和不能确定的分两栏，不确定的列成问题清单去问研发，不许自己定。

产出：规则 1–10 + 冲突清单
4备料与参数

坎：换个站就错——路径前缀段数不固定。
怎么说：这个数不许写死，要么推断并给证据，要么直接停。

产出：映射表 + 参数文件；P 推断 556/556
5写引擎跑通

坎：差点整文件重排（空数组写法、17 位浮点全变）。
怎么说：只在原字符串上换目标字段的值，不许重排文件、不许加新键。

产出：引擎 + 预检/正式四种模式
6全量普查名称

坎：以为改完 partName 就完事，其实名称存了三份。
怎么说：把所有出现旧名称的位置全量普查一遍，一处不许漏，给完整清单。

产出：672 处名称副本同步
7先跑预检

坎：换站一跑 62 条异常，本能想「调成 0」。
怎么说：不许为好看改数据，把 62 条按原因归类，说清每类该怎么办。

产出：预检报告 + 异常清单（缺行 2 / 一对多 17）
8确认后执行

坎：两个都叫「最新」的台账；输出目录还堆着旧文件。
怎么说：哪个最新我不猜，把差异和后果列出来；输出目录必须是新的。

产出：7 个新航线 + 全套报告
9独立验收

坎：程序说「全部成功」，可改错是静默的。
怎么说：再写一个不引用你结论的验收程序，从零重算一遍。

产出：12 项全过；与历史交付 7/7 逐字节一致
10换站与固化

坎：我跑通了，换个人不敢点、不会用。
怎么说：做成别人不用问我也能跑的：填 4 个路径、先预检、我确认再执行。

产出：参数表 + Skill + exe + 12 条弯路清单
十步里最值钱的三条：先让它调查、给证据，再让它动手（2、4、8）　·　把「我不知道」变成问题清单，找能定规则的人定（3、8）　·　让它自己证伪：独立重算 + 逐字节比对（2、9）

3现在怎么用：五步

1
填参数4 个必填路径
2
预检只出报告，不写航线
3
人工确认核对 5 项
4
正式执行输出到新目录
5
独立验收12 项自动重算
必填 4 项：旧航线目录、旧→新映射表（CSV）、新台账（CSV）、输出目录（必须不存在）。 报告目录另外指定，且不得位于输出目录内。

产物位置：<输出目录>\（7 个同名航线）　报告：<报告目录>\（预检报告、汇总、变更明细、异常清单、验收报告）

4三条红线（一定要守住）

不猜规则不确定的找研发确定；路径前缀段数推断不出就中止（退出码 1），不硬跑。
不动原件输入只读；输出目录必须不存在；不许整体重新序列化，只做文本级定点替换。
不说假成功查不到 / 一对多 / 空值一律保持旧值 + 记异常；异常点位不算失败，但必须逐条看得见。

5这个案例证明了两件事

结论证据
结果可信城南变 7 个航线：719/719 处引用更新成功、0 异常；白名单外字节差异 0；与历史交付 7/7 逐字节一致；独立验收 12 项全过（部件名 1439、keyID 790、坐标 1185、名称副本 678、sha256 9）。
能够复用换站（220kV 都梁变，11 个航线 / 1001 个部件点 / 2002 处引用）只改参数文件即跑通：1940 成功、62 异常按设计保持旧值；命令行 / Agent 技能 / 界面三处共用同一份引擎，结果一致。

6九条经验（换场景也适用）

1 需求写清单 + 禁止清单 2 规则不确定找研发确定 3 先把数据探到字节级 4 参数与逻辑分离 5 推断不出来就中止 6 两阶段 + 人工确认 7 每步立即校验，不靠退出码 8 独立验收要换套算法重算 9 界面只是外壳，逻辑只有一份

7命令速查（不影响日常使用）

python update_ledger_generic.py --init-config 站参数.json     :: 生成参数模板（填 4 个路径）
python update_ledger_generic.py -c 站参数.json --dry-run      :: 预检：只出报告，不写航线
python update_ledger_generic.py -c 站参数.json --confirm      :: 正式执行（人工确认后）
python route_ledger_tool.py verify --mapping 映射表.csv ...    :: 独立验收（--mapping 必填）
